## What Was Built

### 1. PropertyRunner Coverage Methods

**File:** `Sources/InvariantSwift/Advanced/PropertyRunner+Coverage.swift`

Implemented two PropertyRunner extension methods for coverage-guided testing:

```swift
extension PropertyRunner {
  // Track coverage while running property tests
  func runPropertyWithCoverageTracking<T>(
    _ property: Property<T>,
    knownSymbols: Set<String>,
    config: PropertyConfig,
    coverageConfig: CoverageConfig
  ) async -> (PropertyResult<T>, CoverageReport)

  // Run property with adaptive coverage-guided generation
  func runPropertyWithCoverageGuidance<T>(
    _ property: Property<T>,
    collector: CoverageCollector,
    config: PropertyConfig,
    coverageStrategy: CoverageStrategy
  ) async -> (PropertyResult<T>, CoverageReport)
}
```

**Implementation approach:**
- **Stub implementation** for now: Returns zero coverage metrics
- Integrates with existing `CoverageReport`, `CoverageCollector`, `CoverageConfig`, `CoverageStrategy` types from `Advanced/CoverageGuided.swift`
- Full LLVM coverage integration deferred to future ISP

**Why Advanced/ directory:**
- Needs `CoverageReport` and related types from `CoverageGuided.swift`
- Core/ would create circular dependency (Core → Advanced)
- Solution: Import `InvariantSwiftCore` in Advanced extension

## Decisions Made

### Decision 1: PropertyRunner+Coverage.swift Location

**Context:** Extension needs access to coverage types (CoverageReport, CoverageCollector) which live in `Advanced/CoverageGuided.swift`

**Options considered:**
1. **Core/** - Would create circular dependency (InvariantSwiftCore → InvariantSwiftExperimental)
2. **Advanced/** - Natural location, import InvariantSwiftCore ✅ Chosen
3. Extract coverage types to Core/ - Large refactor, breaks existing imports

**Decision:** Place in `Advanced/` and import `InvariantSwiftCore`

**Rationale:**
- Avoids circular dependency
- Keeps coverage-related code together
- No breaking changes to existing code
- Simple import statement solves type visibility
