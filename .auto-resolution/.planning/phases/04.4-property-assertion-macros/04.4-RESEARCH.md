# Phase 04.4: Property Assertion Macros (@Idempotent, @Deterministic, @Pure) - Research

**Researched:** 2026-01-23
**Domain:** Swift property-based testing macros
**Confidence:** MEDIUM-HIGH

## Summary

This research focuses on implementing three property assertion macros for common function properties: `@Idempotent`, `@Deterministic`, and `@Pure`. These macros automate testing of critical function behaviors that are foundational to reliable software.

**Key Findings:**
- InvariantSwift has a mature macro infrastructure (PropertyMacro, BusinessRuleMacro, LawCheckedMacro) providing proven patterns
- Pure SwiftSyntax AST builders are mandatory (no string interpolation)
- Property testing infrastructure (PropertyRunner, Property, Gen, ShrinkTree) is battle-tested
- Swift 6 PeerMacro protocol is well-documented with clear best practices
- Idempotent/deterministic/pure function testing patterns are well-understood in property-based testing literature

**Primary recommendation:** Implement three PeerMacros following the PropertyMacro pattern, generating property tests that verify mathematical definitions of each property using the existing PropertyRunner infrastructure.

### Pattern 1: PeerMacro Structure (from PropertyMacro)

**What:** Generate a peer test function that validates the property assertion
**When to use:** All three macros follow this pattern

**Example:**
```swift
// Source: PropertyMacro.swift lines 7-49
public struct IdempotentMacro: PeerMacro {
  public static func expansion(
    of node: AttributeSyntax,
    providingPeersOf declaration: some DeclSyntaxProtocol,
    in context: some MacroExpansionContext
  ) throws -> [DeclSyntax] {
    // 1. Validate function declaration
    guard let funcDecl = declaration.as(FunctionDeclSyntax.self) else {
      context.diagnose(Diagnostic(node: node, message: "Must be function"))
      return []
    }

    // 2. Extract parameters
    let parameters = ParameterExtractor.extract(from: funcDecl)

    // 3. Build test function using AST builders
    let testFunc = buildIdempotentTestFunction(...)

    return [DeclSyntax(testFunc)]
  }
}
```

### Pattern 4: Mathematical Property Definitions

**What:** Encode mathematical definitions as property tests
**When to use:** Each macro tests a specific mathematical property

**@Idempotent Definition:**
```swift
// f(f(x)) == f(x) for all x in domain
let property = Property(generator: gen) { input in
  let once = targetFunction(input)
  let twice = targetFunction(once)
  return once == twice
}
```

**@Deterministic Definition:**
```swift
// f(x) == f(x) for all x (multiple calls return same result)
let property = Property(generator: gen) { input in
  let call1 = targetFunction(input)
  let call2 = targetFunction(input)
  return call1 == call2
}
```

**@Pure Definition:**
```swift
// 1. Deterministic: f(x) == f(x)
// 2. Referentially transparent: f(x) doesn't modify external state
// Note: State modification is hard to detect in Swift, focus on determinism
let property = Property(generator: gen) { input in
  let call1 = targetFunction(input)
  let call2 = targetFunction(input)
  return call1 == call2
}
```

### Anti-Patterns to Avoid

- **String Interpolation for Code Generation:** NEVER use `stringLiteral:` for AST nodes (see CLAUDE.md lines 77-89)
- **Throwing from Expansion:** Return empty array with diagnostic, don't throw (see PropertyMacro pattern)
- **Missing Trivia:** Preserve leading/trailing trivia for proper formatting
- **No Return Type Constraint:** @Idempotent requires function return type is Equatable (must diagnose)

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| AST Node Creation | String concatenation | SwiftSyntaxBuilder DSL | Type safety, trivia preservation |
| Generator Inference | Custom type mapping | `GeneratorInference.infer()` | Already handles 30+ types |
| Parameter Extraction | Manual syntax parsing | `ParameterExtractor.extract()` | Handles edge cases (@Gen, labels) |
| Test Function Naming | Simple concatenation | Utilities/ASTBuilders helpers | Consistent naming, avoids conflicts |
| Diagnostics | Custom error types | `MacroContext.error()` | Standardized error reporting |
| Property Test Execution | Custom runner | `PropertyRunner` + `Property<T>` | Battle-tested, supports shrinking |

**Key insight:** InvariantSwift already has 90% of the infrastructure needed. Don't reinvent parameter extraction, generator inference, or test execution - compose existing utilities.

## Common Pitfalls

### Pitfall 1: Equatable Constraint Missing
**What goes wrong:** @Idempotent generates code comparing function results without checking return type is Equatable
**Why it happens:** Swift macros don't have access to type checker information during expansion
**How to avoid:** Document that return type must be Equatable, emit diagnostic if return type is known non-Equatable (like `Void`)
**Warning signs:** Compiler error in generated code: "Binary operator '==' cannot be applied to operands of type X and X"

### Pitfall 2: Non-Deterministic Functions Pass @Deterministic
**What goes wrong:** Functions with side effects or randomness may appear deterministic in tests
**Why it happens:** Property tests are probabilistic, not exhaustive
**How to avoid:**
- Use sufficient iterations (default 100)
- Document limitations in macro comments
- Consider configurable iteration count via macro parameter
**Warning signs:** Flaky tests that pass sometimes, fail others

### Pitfall 3: State Mutation Detection for @Pure
**What goes wrong:** @Pure cannot detect external state mutations in Swift
**Why it happens:** Swift lacks effect tracking system (unlike Haskell's type system)
**How to avoid:**
- Document that @Pure only checks determinism, not true purity
- Recommend manual review for state mutation
- Consider naming as @DeterministicPure to be explicit
**Warning signs:** Functions with `var` captured variables marked as @Pure

### Pitfall 4: Async Function Support
**What goes wrong:** Async functions need different Property variant (AsyncProperty)
**Why it happens:** Swift 6 strict concurrency requires async predicate support
**How to avoid:**
- Check for `async` in function signature effectSpecifiers
- Use `AsyncProperty<T>` instead of `Property<T>`
- Use `runAsyncProperty` instead of `runProperty`
**Warning signs:** Compiler error about @Sendable closure not matching async function

### Pitfall 5: Iteration Count for Idempotence
**What goes wrong:** Testing f(f(x)) == f(x) only checks 2 iterations, but some functions need 3+ to stabilize
**Why it happens:** Mathematical definition uses 2 iterations, but practical functions may converge slowly
**How to avoid:**
- Provide `iterations` parameter: `@Idempotent(iterations: 3)`
- Default to 2 (mathematical definition)
- Document that this tests "eventual idempotence"
**Warning signs:** Function that normalizes data in multiple passes fails test

### Pitfall 6: Peer Macro Symbol Resolution
**What goes wrong:** Generated test function conflicts with existing symbols
**Why it happens:** PropertyMacro notes this as known issue (lines 139-145)
**How to avoid:**
- Use wrapper enum pattern from PropertyMacro (lines 94-105)
- Generate private enum containing static test method
- Avoids peer+peer macro conflict
**Warning signs:** Swift symbol resolution failures during compilation

### @Idempotent Macro Structure
```swift
// Pattern adapted from PropertyMacro.swift
import SwiftSyntax
import SwiftSyntaxBuilder
import SwiftSyntaxMacros

public struct IdempotentMacro: PeerMacro {
  public static func expansion(
    of node: AttributeSyntax,
    providingPeersOf declaration: some DeclSyntaxProtocol,
    in context: some MacroExpansionContext
  ) throws -> [DeclSyntax] {
    let ctx = MacroContext(context: context)

    guard let funcDecl = declaration.as(FunctionDeclSyntax.self) else {
      ctx.error(IdempotentDiagnostic.mustBeFunction, at: node)
      return []
    }

    // Extract configuration from macro arguments
    let config = extractIdempotentConfig(from: node)

    // Build test function
    let testFunc = buildIdempotentTest(
      funcDecl: funcDecl,
      config: config,
      context: ctx
    )

    return [DeclSyntax(testFunc)]
  }
}

struct IdempotentConfig {
  let iterations: Int  // How many times to apply f(f(x))
  let testIterations: Int  // PropertyConfig iterations

  static let `default` = Self(iterations: 2, testIterations: 100)
}
```

### Generator Inference for Multiple Parameters
```swift
// Source: PropertyMacro.swift lines 192-237
// Build combined generator for function parameters
private static func buildGeneratorDeclaration(
  parameters: [ExtractedParameter]
) -> VariableDeclSyntax {
  let generators = parameters.map { param -> ExprSyntax in
    // Use @Gen attribute if provided, otherwise infer
    if let genAttr = ParameterExtractor.extractGenAttribute(param) {
      return GeneratorDSL.parse(from: genAttr)
    }
    return GeneratorInference.infer(for: param.type)
  }

  // Single parameter: just use that generator
  if generators.count == 1 {
    return VariableDeclSyntax(
      bindingSpecifier: .keyword(.let),
      bindings: PatternBindingListSyntax {
        PatternBindingSyntax(
          pattern: IdentifierPatternSyntax(identifier: .identifier("generator")),
          initializer: InitializerClauseSyntax(value: generators[0])
        )
      }
    )
  }

  // Multiple parameters: combine with flatMap chain
  let paramNames = parameters.map { $0.name }
  let combinedGen = buildFlatMapChain(generators, parameterNames: paramNames)

  return VariableDeclSyntax(
    bindingSpecifier: .keyword(.let),
    bindings: PatternBindingListSyntax {
      PatternBindingSyntax(
        pattern: IdentifierPatternSyntax(identifier: .identifier("generator")),
        initializer: InitializerClauseSyntax(value: combinedGen)
      )
    }
  )
}
```

### Idempotent Property Test Body
```swift
// Build the property test that checks f(f(x)) == f(x)
private static func buildIdempotentProperty(
  funcDecl: FunctionDeclSyntax,
  parameters: [ExtractedParameter],
  config: IdempotentConfig
) -> CodeBlockSyntax {
  CodeBlockSyntax {
    // 1. Generator declaration
    buildGeneratorDeclaration(parameters: parameters)

    // 2. Property definition
    VariableDeclSyntax(
      bindingSpecifier: .keyword(.let),
      bindings: PatternBindingListSyntax {
        PatternBindingSyntax(
          pattern: IdentifierPatternSyntax(identifier: .identifier("property")),
          initializer: InitializerClauseSyntax(
            value: FunctionCallExprSyntax(
              calledExpression: DeclReferenceExprSyntax(baseName: .identifier("Property")),
              leftParen: .leftParenToken(),
              arguments: LabeledExprListSyntax {
                LabeledExprSyntax(
                  label: .identifier("generator"),
                  colon: .colonToken(),
                  expression: DeclReferenceExprSyntax(baseName: .identifier("generator"))
                )
              },
              rightParen: .rightParenToken(),
              trailingClosure: buildIdempotentClosure(
                funcName: funcDecl.name.text,
                parameters: parameters,
                iterations: config.iterations
              )
            )
          )
        )
      }
    )

    // 3. PropertyConfig
    buildConfigDeclaration(iterations: config.testIterations)

    // 4. PropertyRunner execution
    buildResultDeclaration(isAsync: funcDecl.signature.effectSpecifiers?.asyncSpecifier != nil)

    // 5. Result handling
    buildResultSwitch()
  }
}

// Build closure: { args in f(f(args)) == f(args) }
private static func buildIdempotentClosure(
  funcName: String,
  parameters: [ExtractedParameter],
  iterations: Int
) -> ClosureExprSyntax {
  ClosureExprSyntax(
    signature: ClosureSignatureSyntax(
      parameterClause: .parameterClause(
        ClosureParameterClauseSyntax(
          parameters: ClosureParameterListSyntax {
            for param in parameters {
              ClosureParameterSyntax(
                firstName: .identifier(param.name),
                colon: .colonToken(),
                type: param.type
              )
            }
          }
        )
      )
    ),
    statements: CodeBlockItemListSyntax {
      // var current = originalInput
      // for _ in 0..<iterations { current = f(current) }
      // let next = f(current)
      // return current == next
    }
  )
}
```

### Diagnostic Emission Pattern
```swift
// Source: Utilities/DiagnosticEmitter.swift pattern
public enum IdempotentDiagnostic: String, MacroDiagnostic {
  public static let domain = "InvariantSwift.IdempotentMacro"

  case mustBeFunction = "must_be_function"
  case mustReturnEquatable = "must_return_equatable"
  case noParameters = "no_parameters"

  public var severity: DiagnosticSeverity { .error }

  public var message: String {
    switch self {
    case .mustBeFunction:
      return "@Idempotent can only be applied to functions"
    case .mustReturnEquatable:
      return "@Idempotent requires return type to be Equatable"
    case .noParameters:
      return "@Idempotent requires at least one parameter"
    }
  }
}
```

## Open Questions

1. **@Pure Side Effect Detection**
   - What we know: Swift lacks effect tracking like Haskell's type system
   - What's unclear: Best approach - document limitations vs. attempt runtime detection
   - Recommendation: Document that @Pure only tests determinism, recommend manual review for state mutation. Consider naming `@DeterministicPure` to be explicit.

2. **Async Function Support**
   - What we know: InvariantSwift supports AsyncProperty<T> (Property.swift lines 319-342)
   - What's unclear: Should macros automatically detect async and use AsyncProperty?
   - Recommendation: Yes, check `effectSpecifiers?.asyncSpecifier` and generate AsyncProperty accordingly (see PropertyMacro pattern)

3. **Iteration Count Configuration**
   - What we know: Idempotence mathematically requires f(f(x)) == f(x)
   - What's unclear: Should macro support `@Idempotent(iterations: 3)` for functions that converge slowly?
   - Recommendation: Add optional `iterations` parameter (default 2), test convergence at that point

4. **Equatable Constraint Enforcement**
   - What we know: Swift macros don't have access to type checker
   - What's unclear: How to ensure return type is Equatable?
   - Recommendation: Document requirement, emit diagnostic for known non-Equatable types (Void), let compiler catch others
