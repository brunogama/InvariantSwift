Focus new development on: (1) `@Timeout` macro using Swift Concurrency `withTaskCancellationHandler` pattern, (2) property combinators as operator overloads on `Property<T>`, (3) `forAll` function with automatic generator inference via type constraints, (4) HTML report generation extending the existing `Doc` system.

### Pattern 1: Swift Concurrency Timeout

**What:** Use `withTaskCancellationHandler` + racing tasks for cooperative timeout
**When to use:** Property test execution with time limits
**Example:**
```swift
// Source: Swift Forums pattern verified
public func withTimeout<T>(
  seconds: TimeInterval,
  operation: @escaping () async throws -> T
) async throws -> T {
  try await withThrowingTaskGroup(of: T.self) { group in
    group.addTask {
      try await operation()
    }
    group.addTask {
      try await Task.sleep(nanoseconds: UInt64(seconds * 1_000_000_000))
      throw TimeoutError(elapsed: seconds)
    }
    let result = try await group.next()!
    group.cancelAll()
    return result
  }
}
```

### Pattern 2: Property Combinator Operators

**What:** Operator overloads for logical property composition
**When to use:** Combining multiple properties in tests
**Example:**
```swift
// Logical AND with short-circuit
public func && <T>(lhs: Property<T>, rhs: Property<T>) -> Property<T> {
  Property(generator: lhs.generator) { value in
    lhs.predicate(value) && rhs.predicate(value)
  }
}

// Implication: precondition => property
public func implies<T>(_ precondition: @escaping (T) -> Bool, _ property: Property<T>) -> Property<T> {
  Property(generator: property.generator) { value in
    !precondition(value) || property.predicate(value)
  }
}
```

### Pattern 3: forAll with Type Inference

**What:** Global function inferring generators from closure parameter types
**When to use:** Ergonomic property definition without explicit generators
**Example:**
```swift
// Source: QuickCheck/fast-check pattern adapted for Swift
public func forAll<A: Arbitrary>(
  _ check: @escaping (A) -> Bool
) -> Property<A> {
  Property(generator: A.arbitrary, predicate: check)
}

// Multi-parameter variant
public func forAll<A: Arbitrary, B: Arbitrary>(
  _ check: @escaping (A, B) -> Bool
) -> Property<(A, B)> {
  Property(
    generator: Gen.zip(A.arbitrary, B.arbitrary),
    predicate: { check($0.0, $0.1) }
  )
}

// Explicit generator variant
public func forAll<A>(
  _ gen: Gen<A>,
  check: @escaping (A) -> Bool
) -> Property<A> {
  Property(generator: gen, predicate: check)
}
```

### Pattern 4: Generator Middleware/Interceptor

**What:** Protocol-based interceptor chain for generation/shrinking observability
**When to use:** Logging, validation, metrics collection
**Example:**
```swift
// Source: Interceptor pattern from gRPC middleware
public protocol GeneratorInterceptor: Sendable {
  func onGenerate<T>(_ value: T, generator: Gen<T>, size: Size) -> T
  func onShrink<T>(_ original: T, shrunk: T, step: Int) -> T
  func onPropertyEvaluated<T>(_ value: T, passed: Bool)
}

extension Gen {
  public func withInterceptor(_ interceptor: GeneratorInterceptor) -> Gen<T> {
    Gen<T>(
      generate: { rng, size in
        let value = self.generate(&rng, size)
        return interceptor.onGenerate(value, generator: self, size: size)
      },
      shrink: Shrink { value in
        let shrunk = self.shrink.shrink(value)
        return shrunk.enumerated().map { idx, s in
          interceptor.onShrink(value, shrunk: s, step: idx)
        }
      }
    )
  }
}
```

### Pattern 5: Parallel Shrinking with Task Groups

**What:** Concurrent exploration of shrink tree branches using Swift Concurrency
**When to use:** Large shrink trees where parallel exploration can find minimal counterexamples faster
**Example:**
```swift
// Source: ShrinkTree.swift extended with concurrency
extension ShrinkTree {
  public func findMinimalParallel(
    budget: Int,
    workers: Int = ProcessInfo.processInfo.processorCount,
    satisfying predicate: @escaping @Sendable (T) async -> Bool
  ) async -> T? {
    guard await predicate(value) else { return nil }

    return await withTaskGroup(of: T?.self) { group in
      var best: T = value
      var queue: [ShrinkTree<T>] = children
      var visited = 0

      // Distribute initial work to workers
      for child in queue.prefix(workers) {
        group.addTask {
          await child.findMinimalAsync(budget: budget / workers, satisfying: predicate)
        }
      }

      for await result in group {
        if let found = result {
          // Found a smaller counterexample
          best = found
        }
      }

      return best
    }
  }
}
```

### Anti-Patterns to Avoid

- **Non-cooperative timeout:** Using `DispatchQueue.asyncAfter` without `Task.checkCancellation()` - causes resource leaks
- **Eager shrink tree evaluation:** Computing all children upfront - defeats lazy evaluation benefits
- **Blocking in async context:** Using `Thread.sleep` instead of `Task.sleep` - blocks thread pool
- **Global state in interceptors:** Using class-level vars - breaks `Sendable` requirements
- **HTML string concatenation:** Building reports with `+` - injection risks, poor performance

## Common Pitfalls

### Pitfall 1: Timeout Race Conditions

**What goes wrong:** Multiple tasks completing simultaneously, result lost or duplicated
**Why it happens:** Not using `group.cancelAll()` after first result
**How to avoid:** Always cancel remaining tasks, use atomic result handling
**Warning signs:** Intermittent "result already set" crashes, test flakiness

### Pitfall 2: Sendable Violations in Closures

**What goes wrong:** Compiler errors when capturing mutable state in async contexts
**Why it happens:** Swift 6 strict concurrency checking
**How to avoid:** Use `@Sendable` closures, actors for shared state, immutable captures
**Warning signs:** "Capture of '...' with non-sendable type" warnings

### Pitfall 3: forAll Type Inference Failure

**What goes wrong:** Compiler can't infer generic types for complex closures
**Why it happens:** Swift type inference limitations with multiple generic parameters
**How to avoid:** Require explicit type annotations, provide helpful error messages
**Warning signs:** "Generic parameter 'T' could not be inferred" errors

### Pitfall 4: HTML Report Memory Explosion

**What goes wrong:** OOM when generating reports for tests with millions of iterations
**Why it happens:** Storing all generated values in memory
**How to avoid:** Use streaming/sampling, pagination, summary statistics
**Warning signs:** Memory spikes during report generation, slow test completion

### Pitfall 5: Parallel Shrinking Non-Determinism

**What goes wrong:** Same seed produces different minimal counterexamples
**Why it happens:** Race conditions in parallel exploration, order-dependent results
**How to avoid:** Track all minimal candidates, select deterministically (e.g., lexicographically smallest)
**Warning signs:** Flaky tests that "pass" with different shrunk values

### Pitfall 6: Middleware Performance Overhead

**What goes wrong:** Tests become 10x slower with middleware enabled
**Why it happens:** Synchronous interceptor calls on every generation
**How to avoid:** Make interceptors opt-in, use sampling, batch notifications
**Warning signs:** Test suite runtime increases linearly with middleware count

### Property Combinators (QuickCheck-style)

```swift
// Source: QuickCheck Test.QuickCheck.Property module
extension Property {
  /// Logical conjunction: both properties must hold
  public static func && (lhs: Property<T>, rhs: Property<T>) -> Property<T> {
    Property(generator: lhs.generator) { value in
      guard lhs.predicate(value) else { return false }  // Short-circuit
      return rhs.predicate(value)
    }
  }

  /// Logical disjunction: at least one property must hold
  public static func || (lhs: Property<T>, rhs: Property<T>) -> Property<T> {
    Property(generator: lhs.generator) { value in
      if lhs.predicate(value) { return true }  // Short-circuit
      return rhs.predicate(value)
    }
  }

  /// Implication: if precondition holds, property must hold
  public func implies(_ precondition: @escaping (T) -> Bool) -> Property<T> {
    Property(generator: generator) { value in
      !precondition(value) || self.predicate(value)
    }
  }
}
```

### Generator Middleware Implementation

```swift
// Source: Interceptor pattern adapted from gRPC middleware
public final class LoggingInterceptor: GeneratorInterceptor, @unchecked Sendable {
  private let output: @Sendable (String) -> Void

  public init(output: @escaping @Sendable (String) -> Void = { print($0) }) {
    self.output = output
  }

  public func onGenerate<T>(_ value: T, generator: Gen<T>, size: Size) -> T {
    output("Generated: \(value) (size: \(size.value))")
    return value
  }

  public func onShrink<T>(_ original: T, shrunk: T, step: Int) -> T {
    output("Shrink[\(step)]: \(original) -> \(shrunk)")
    return shrunk
  }

  public func onPropertyEvaluated<T>(_ value: T, passed: Bool) {
    output("Evaluated: \(passed ? "PASS" : "FAIL") for \(value)")
  }
}

public final class MetricsInterceptor: GeneratorInterceptor, @unchecked Sendable {
  public struct Metrics: Sendable {
    public var generationCount: Int = 0
    public var shrinkSteps: Int = 0
    public var passCount: Int = 0
    public var failCount: Int = 0
  }

  private let _metrics = OSAllocatedUnfairLock(initialState: Metrics())

  public var metrics: Metrics {
    _metrics.withLock { $0 }
  }

  public func onGenerate<T>(_ value: T, generator: Gen<T>, size: Size) -> T {
    _metrics.withLock { $0.generationCount += 1 }
    return value
  }

  public func onShrink<T>(_ original: T, shrunk: T, step: Int) -> T {
    _metrics.withLock { $0.shrinkSteps += 1 }
    return shrunk
  }

  public func onPropertyEvaluated<T>(_ value: T, passed: Bool) {
    _metrics.withLock {
      if passed { $0.passCount += 1 }
      else { $0.failCount += 1 }
    }
  }
}
```

## Open Questions

Things that couldn't be fully resolved:

1. **@Timeout macro implementation approach**
   - What we know: Swift macros can wrap function bodies, `@attached(body)` macro type exists
   - What's unclear: Best way to integrate with @PropertyTest - composition vs. single macro
   - Recommendation: Start with composition (`@Timeout @PropertyTest`), consider merging later

2. **forAll type inference limits**
   - What we know: Swift can infer up to 6 tuple elements reliably
   - What's unclear: Edge cases with associated types, protocol witnesses
   - Recommendation: Provide explicit generator variants for complex cases, add helpful diagnostics

3. **Parallel shrinking determinism**
   - What we know: Multiple threads can find different "minimal" values
   - What's unclear: Whether users expect determinism or accept faster-but-variable results
   - Recommendation: Provide both modes - deterministic (sequential) and fast (parallel)

4. **CLI catalog interactivity**
   - What we know: swift-argument-parser supports interactive mode basics
   - What's unclear: Whether full TUI (curses-style) is needed or simple menu suffices
   - Recommendation: Start with simple menu/listing, add TUI in future iteration
