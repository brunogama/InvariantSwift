# Phase 04.3 Plan 01: @Equivalence Macro Core Infrastructure - Summary

**One-liner:** Implemented @Equivalence macro with BinaryFloatingPoint tolerance validation using pure SwiftSyntax AST builders and GeneratorInference integration

## What Was Built

Created complete @Equivalence macro infrastructure for function equivalence testing with floating-point tolerance support:

### 1. Macro Declaration (Sources/InvariantSwift/Macros/EquivalenceMacroDeclaration.swift)
- `@attached(peer, names: suffixed(_EquivalenceTest))` macro definition
- Parameters: `iterations: Int = 500`, `tolerance: Double? = nil`
- Comprehensive documentation with usage examples for refactoring validation and algorithm comparison
- References `#externalMacro(module: "InvariantSwiftMacros", type: "EquivalenceMacro")`

### 2. Diagnostic System (EquivalenceDiagnostic.swift)
- Four diagnostic message types:
  - `mustBeFunction`: Macro applied to non-function
  - `requiresTwoFunctionParameters`: Wrong parameter count
  - `incompatibleFunctionTypes`: Mismatched function signatures
  - `toleranceRequiresBinaryFloatingPoint`: Invalid tolerance usage

### 3. Configuration Extraction (EquivalenceConfigExtractor.swift)
- `EquivalenceMacroConfig` struct with `iterations` and `tolerance` properties
- `extract(from: AttributeSyntax)` static method parses macro attributes
- Handles both `FloatLiteralExprSyntax` and `IntegerLiteralExprSyntax` for tolerance values

### 4. Macro Implementation (EquivalenceMacro.swift, 496 lines)
**Validation Pipeline:**
- Validates declaration is `FunctionDeclSyntax` (emits `mustBeFunction` diagnostic)
- Extracts parameters via `ParameterExtractor.extract(from:)`
- Validates exactly 2 parameters (emits `requiresTwoFunctionParameters` diagnostic)
- Validates both parameters are function types (emits `incompatibleFunctionTypes` diagnostic)
- **CRITICAL:** Validates tolerance only used with BinaryFloatingPoint types (Double, Float, Float16, Float80, CGFloat)

**Code Generation:**
- Infers input generators using `GeneratorInference.infer(for: inputType)`
- Combines multiple inputs with `FunctionCallBuilder.genZip(generators)`
- Builds wrapper enum with `@Test` static function (follows PropertyMacro pattern)
- Generates test body with iteration loop (0..<iterations)
- Calls reference and candidate functions with generated input
- Compares results:
  - **WITHOUT tolerance:** Uses `!=` operator via `InfixOperatorExprSyntax`
  - **WITH tolerance:** Builds `referenceResult.isApproximatelyEqual(to: candidateResult, tolerance: .absolute(tolerance))` via:
    - `MemberAccessExprSyntax` for `.absolute` enum case
    - `FunctionCallExprSyntax` with tolerance value
    - `FunctionCallExprSyntax` for instance method call
    - `PrefixOperatorExprSyntax` for negation (divergence check)
- Reports divergences via `Issue.record`

**Pure AST Construction:**
- Zero string interpolation (all AST builders)
- Type-safe SwiftSyntax APIs
- Trivia-preserving code generation

### 5. Macro Registration
- Added `EquivalenceMacro.self` to `MacroPlugin.providingMacros` array
- Positioned after `@Idempotent`, `@Deterministic`, `@Pure` for logical grouping
