## Technical Decisions

### Decision 1: Timeout Only for Async Properties

**Rationale:** Synchronous property tests run on the calling thread. Wrapping with `withPropertyTimeout` would block the thread waiting for the timeout timer, defeating the purpose. Only async properties can cooperatively cancel via Swift Concurrency.

**Implementation:** `buildResultDeclaration(timeoutConfig:)` ignores `timeoutConfig` - no wrapper generated. Only `buildAsyncResultDeclaration(timeoutConfig:)` applies the wrapper.

**Trade-off:** Users might expect timeout on sync properties to work, but the behavior would be incorrect (blocked thread). Clear documentation prevents confusion.

### Decision 2: Wrapper Only When Timeout Present

**Rationale:** Avoid overhead when no timeout configured. The generated code should be as clean as possible when features aren't used.

**Implementation:**
```swift
if let timeout = timeoutConfig, let seconds = timeout.seconds {
  // Generate withPropertyTimeout wrapper
} else {
  // Direct await runPropertyAsync call
}
```

**Benefit:** Zero-cost abstraction - no timeout overhead unless explicitly requested.

### Decision 3: parseFunctionDecl Helper for Tests

**Rationale:** SwiftLint `force_try` rule prevents using `try!` without `swiftlint:disable:next` comments. Instead of 13 disable comments, centralize the force try in a single helper function.

**Implementation:**
```swift
private func parseFunctionDecl(_ source: String) -> FunctionDeclSyntax? {
  // swiftlint:disable:next force_try
  let parsed = try! Parser.parse(source: source)
  return parsed.statements.first?.item.as(FunctionDeclSyntax.self)
}
```

**Benefit:** Single disable comment, cleaner test code, easier to maintain.

## Performance Considerations

**Task Racing Overhead:** `withPropertyTimeout` creates two concurrent tasks (operation + timer). Negligible overhead (~microseconds) for property tests that run milliseconds to seconds.

**Cancellation Cost:** Task cancellation is lightweight in Swift Concurrency (cooperative cancellation points). No measurable impact on test performance.

**Memory:** Minimal - two Task handles in task group, cleaned up immediately after first task completes.

## Known Limitations

1. **Timeout only for async properties** - Sync properties cannot be timed out without blocking threads
2. **No macro expansion tests** - Deferred due to whitespace sensitivity; extractor tests verify parsing logic
3. **No timeout failure end-to-end test** - Existing `TimeoutTests.swift` covers runtime behavior; macro tests focus on generation
