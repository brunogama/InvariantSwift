- Parameters: `iterations: Int = 100`, `callCount: Int = 2`
- Use cases: safe for memoization, safe for parallelization, self-documenting contracts
- Examples: arithmetic operations, pure computations

## Key Implementation Details

### Documentation Structure Pattern

Established consistent pattern for macro documentation:

1. **Purpose statement** with one-line summary
2. **Mathematical definition** for formal correctness
3. **Parameters table** with types, defaults, descriptions
4. **Requirements** for valid usage
5. **Use cases** with practical scenarios
6. **Examples** showing basic and custom configuration usage
7. **Limitations** prominently displayed for macros with constraints

### @Pure Limitation Documentation

The @Pure macro documentation includes multiple warnings:

- **"Important Limitation" header** at the top
- **"What @Pure Tests" vs "What @Pure CANNOT Test"** comparison
- **Bullet list** of undetectable side effects (state mutation, I/O, global state)
- **Recommendation section** advising code review for true purity
- **Repeated in COOKBOOK.md** with note emphasizing manual review

This ensures users understand Swift's lack of effect tracking and don't rely solely on the macro for purity verification.

### Parameter Verification Process

For each macro declaration file:
1. Read actual parameter declarations
2. Verify parameter names match documentation
3. Verify parameter types match documentation
4. Verify default values match documentation
5. Verify @attached attribute matches documentation

All verifications passed without requiring documentation updates.
