# Phase 04.4 Plan 01: @Idempotent and @Deterministic Macro Implementation Summary

**One-liner:** Implemented @Idempotent and @Deterministic PeerMacros generating property tests for idempotency and determinism verification with automatic generator inference and async support.

## What Was Built

### Core Macro Declarations (Sources/InvariantSwift/Macros/)

**IdempotentMacroDeclaration.swift:**
- Public @Idempotent macro declaration
- Parameters: `iterations: Int = 100`, `applicationCount: Int = 2`
- `@attached(peer, names: suffixed(_IdempotentTest))` attribute
- External macro binding to IdempotentMacro.self
- Comprehensive documentation with mathematical definition, use cases (data normalization, caching, retry logic), requirements, and expansion examples

**DeterministicMacroDeclaration.swift:**
- Public @Deterministic macro declaration
- Parameters: `iterations: Int = 100`, `callCount: Int = 2`
- `@attached(peer, names: suffixed(_DeterministicTest))` attribute
- External macro binding to DeterministicMacro.self
- Comprehensive documentation with mathematical definition, use cases (hashing, serialization, reproducibility), requirements, and expansion examples

### Macro Implementations (Sources/InvariantSwiftMacros/PropertyAssertionMacros/)

**PropertyAssertionDiagnostics.swift:**
- Shared diagnostic enum for validation errors
- Cases: `mustBeFunction`, `mustHaveParameters`, `returnTypeMustBeEquatable`, `voidReturnNotAllowed`
- Conforms to MacroDiagnostic protocol with domain "InvariantSwift.PropertyAssertionMacro"
- Clear, actionable error messages

**IdempotentMacro.swift (540 lines):**
- PeerMacro implementation generating property test for f(f(x)) == f(x)
- Validates: declaration is function, has parameters, return type not Void
- Extracts config from macro arguments (iterations, applicationCount)
- Detects async functions via effectSpecifiers
- Generates private wrapper enum containing @Test static function
- Builds generator declaration using GeneratorInference.infer()
- Creates property closure applying function `applicationCount` times, then once more, verifying equality
- Supports single and multiple parameters with automatic tuple handling
- Result handling with switch on .success/.failure/.gaveUp
- SwiftLint compliant with inline disable comments

**DeterministicMacro.swift (522 lines):**
- PeerMacro implementation generating property test for f(x) == f(x) across calls
- Same validation and structure as IdempotentMacro
- Extracts callCount from macro arguments
- Creates property closure calling function multiple times with same input, verifying all results match
- Simplified test body for callCount=2: `call1 = f(input); call2 = f(input); return call1 == call2`
- Identical SwiftLint compliance pattern

**MacroPlugin.swift:**
- Registered `IdempotentMacro.self` and `DeterministicMacro.self` in providingMacros array
- Enables macro compilation and external macro binding

## Key Technical Details

### Wrapper Enum Pattern
```swift
// Generated code structure:
private enum normalize_IdempotentTest {
  @Test static func run() throws {
    let generator = Gen<String>.string
    let property = Property(generator: generator) { text in
      var current = normalize(text)
      for _ in 1..<2 {
        current = normalize(current)
      }
      let next = normalize(current)
      return current == next
    }
    let config = PropertyConfig(iterations: 100, maxShrinks: 1000)
    let result = runPropertySynchronously(property, config: config)
    switch result {
    case .success: break
    case .failure: Issue.record(Comment(stringLiteral: "Idempotency property violated"))
    case .gaveUp: Issue.record(Comment(stringLiteral: "Property test gave up"))
    }
  }
}
```

### Generator Inference
- Both macros use `GeneratorInference.infer(for: param.type)` to automatically select appropriate generators
- Supports primitives (Int, String, Bool, etc.), collections (Array, Set, Dictionary), optionals, and custom types with .arbitrary
- For multiple parameters, builds flatMap chain to combine generators
- Example: `@Idempotent func process(a: Int, b: String) -> Result` → infers `Gen<Int>` and `Gen<String>`, combines into `Gen<(Int, String)>`

### Async Function Support
- Detects async via `funcDecl.signature.effectSpecifiers?.asyncSpecifier != nil`
- Generates async throws signature for test function when needed
- Uses `await` keyword in function calls within property closure
- Uses `runPropertyAsync()` instead of `runPropertySynchronously()`

## Deviations from Plan

None - plan executed exactly as written.

## Decisions Made

1. **Wrapper Enum Pattern:** Use private wrapper enum to avoid peer+peer macro conflict (same as PropertyMacro)
2. **String Interpolation for Closures:** Use ExprSyntax(stringLiteral:) for complex closure bodies (same as PropertyMacro)
3. **Shared Diagnostics:** Single PropertyAssertionDiagnostics enum for both macros (DRY principle)
4. **Inline SwiftLint Disables:** Use swiftlint:disable:next for unavoidable macro boilerplate (same as PropertyMacro)
