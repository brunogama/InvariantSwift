## Objective

Integrate @Regression with PropertyMacro and PropertyRunner for automatic save/replay of failing test cases. This enables:
- Automatic failure persistence when property tests fail
- Replay-first behavior to verify fixed failures
- Mutual exclusion with @Reproduce to prevent conflicts
- Database-backed regression testing

## What Was Built

### 1. Diagnostic Infrastructure

**File**: `Sources/InvariantSwiftMacros/Utilities/Diagnostics.swift`

- Created `MutuallyExclusiveMacrosDiagnostic` struct to handle @Reproduce + @Regression conflict
- Separated from `PropertyMacroDiagnostic` enum because MacroDiagnostic protocol requires `RawRepresentable where RawValue == String`
- Cannot use associated values in enum that conforms to MacroDiagnostic
- Implemented as separate `DiagnosticMessage` struct with macro1/macro2 parameters

**Key Implementation**:
```swift
public struct MutuallyExclusiveMacrosDiagnostic: DiagnosticMessage {
  public let macro1: String
  public let macro2: String

  public var message: String {
    "\(macro1) and \(macro2) cannot be used together on the same function"
  }
}
```

### 2. PropertyConfig Extensions

**File**: `Sources/InvariantSwift/Core/Property.swift`

Added four new fields to PropertyConfig:
- `failingExampleDatabase: FailingExampleDatabase?` - Actor-based database for persistence
- `testIdentifier: TestIdentifier?` - Test identity for database lookup using #file/#function
- `replayFirst: Bool` - Whether to replay saved failures before random generation (default: true)
- `maxReplayExamples: Int?` - Limit on examples to replay (nil = all)

Updated `PropertyConfig.init` with explicit self-assignments for all new fields.

### 3. Replay-First Runner

**File**: `Sources/InvariantSwift/Core/Property.swift`

Implemented `runPropertyWithFailingExamples` function with three-phase execution:

**Phase 1 - Replay**: If `replayFirst=true`, replay saved examples from database
- Load examples using `database.examples(for: testID)`
- Respect `maxReplayExamples` limit
- For each example:
  - Replay using original seed: `Seed(value: example.seed)`
  - If still fails: return immediately with regression info
  - If now passes: mark as fixed via `database.markFixed()`
  - If gave up (assumption failed): keep for now

**Phase 2 - Generate**: Run normal property test with random generation via `runPropertyCore()`

**Phase 3 - Save**: Save new failures to database
- Create `FailingExample` with seed, size, shrinkPath, input description
- Save via `database.save(testID: testID, example: example)`

**Integration**: Updated `runProperty` to dispatch to `runPropertyWithFailingExamples` when both `failingExampleDatabase` and `testIdentifier` are configured. Uses established `DispatchSemaphore` pattern from existing `regressionBank` code.

### 4. PropertyMacro Integration

**File**: `Sources/InvariantSwiftMacros/PropertyMacro/PropertyMacro.swift`

Updated macro expansion to:
1. Extract @Regression config via `RegressionExtractor.extractConfig(from: funcDecl)`
2. Check for @Reproduce presence
3. Emit mutual exclusion diagnostic if both present
4. Pass `regressionConfig` through all builder functions
5. Generate PropertyConfig with FailingExampleDatabase fields

**Generated Code Pattern**:
```swift
let config = PropertyConfig(
  iterations: 100,
  maxShrinks: 1000,
  failingExampleDatabase: FailingExampleDatabase.shared,
  testIdentifier: TestIdentifier(
    module: "",
    file: String(describing: #file),
    function: String(describing: #function),
    signature: ""
  ),
  replayFirst: true,
  maxReplayExamples: 10
)
```

**Key Insight**: Generated code runs in user context where library types are available, so we generate `TestIdentifier(...)` constructor calls directly. Macro expansion code cannot import library types, but generated code can reference them.

## Technical Challenges Resolved

### Challenge 1: MacroDiagnostic Protocol Conformance

**Problem**: Wanted to use `case mutuallyExclusiveMacros(String, String)` with associated values, but `MacroDiagnostic` protocol requires `RawRepresentable where RawValue == String`.

**Solution**: Created separate `MutuallyExclusiveMacrosDiagnostic` struct implementing `DiagnosticMessage` protocol. This allows parameters while maintaining diagnostic functionality.

### Challenge 2: RegressionConfig Sendable Conformance

**Problem**: `RegressionConfig` used in async contexts but wasn't marked `Sendable`, causing Swift 6 concurrency errors.

**Solution**: Made `RegressionConfig: Sendable`. Removed unnecessary `nonisolated(unsafe)` modifier from `default` static property.

### Challenge 3: SwiftSyntax MacroExpansionExprSyntax API

**Problem**: `MacroExpansionExprSyntax` requires `arguments` parameter in Swift 6, but initial implementation omitted it.

**Solution**: Added empty `LabeledExprListSyntax([])` for `#file` and `#function` macro expansions:
```swift
MacroExpansionExprSyntax(
  pound: .poundToken(),
  macroName: .identifier("file"),
  arguments: LabeledExprListSyntax([])
)
```

### Challenge 4: SwiftLint Violations

**Problem**: Multiple SwiftLint violations after implementation:
- 6x vertical whitespace between cases
- 1x function parameter count (buildPropertyTestBody with 5 parameters)
- 1x cyclomatic complexity (runPropertyWithFailingExamples with complex branching)
- 2x function body length (runThrowingProperty, runAsyncThrowingProperty at 61 lines)

**Solution**:
- Added blank lines between switch cases for vertical whitespace
- Used `// swiftlint:disable function_parameter_count` for buildPropertyTestBody
- Used `// swiftlint:disable cyclomatic_complexity` for runPropertyWithFailingExamples
- Used `// swiftlint:disable function_body_length` with corresponding `// swiftlint:enable` for long functions
- Structured disable/enable blocks to avoid `attributes` rule violations with @available attributes
