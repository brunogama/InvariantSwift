# Phase 4.5: @Regression — Auto-Save Failing Cases - Research

**Researched:** 2026-01-23
**Domain:** Swift Macros, Property-Based Testing, Persistent Failure Tracking
**Confidence:** HIGH

## Summary

Phase 4.5 implements the `@Regression` macro to automatically save failing test cases to the FailingExampleDatabase and replay them before random generation. This differs from the existing `@Reproduce` macro (manual reproduction) by providing automatic save + replay-first capability without manual intervention.

**Key findings:**
- ISP-0004 infrastructure (FailingExampleDatabase, TestIdentifier, FailingExample) is fully implemented
- @Reproduce macro exists as a marker macro (peer) that configures PropertyMacro expansion
- @Regression should follow the same attached peer macro pattern
- Integration point: PropertyConfig already supports regressionBank, but current implementation uses seeds
- Need to bridge FailingExampleDatabase (ISP-0004 storage) with RegressionBank (existing PropertyRunner integration)

**Primary recommendation:** Implement @Regression as an attached peer macro that configures PropertyMacro to use FailingExampleDatabase for automatic save/replay, with minimal code duplication from @Reproduce.

## Architecture Patterns

### @Regression vs @Reproduce Architecture

**Key Difference:**
```swift
// @Reproduce - MANUAL reproduction (developer adds after failure)
@PropertyTest
@Reproduce(seed: 0xDEADBEEF, size: 42)
func testSorting(array: [Int]) { ... }

// @Regression - AUTOMATIC save + replay-first (no manual work)
@PropertyTest
@Regression(database: .shared, replayFirst: true)
func testSorting(array: [Int]) { ... }
```

**Similarities:**
- Both are `PeerMacro` (don't generate peers themselves)
- Both act as markers that PropertyMacro reads
- Both configure PropertyConfig during expansion

**Implementation Pattern from ReproduceMacro:**

**@Regression follows the same pattern:**
- Marker macro (returns empty array)
- Extracted by PropertyMacro via custom extractor (like ReproduceExtractor)
- Configuration passed to PropertyConfig during expansion

### Anti-Patterns to Avoid

- **❌ String interpolation for code generation:** Use SwiftSyntax AST builders only
- **❌ Macro accessing InvariantSwift library:** Macros can't import the main library
- **❌ Duplicate @Reproduce logic:** Reuse ReproduceExtractor patterns
- **❌ Hardcoding database paths:** Use FailingExampleConfig environment variables

## Don't Hand-Roll

Problems that look simple but have existing solutions:

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Parsing macro attributes | Custom string parsing | `AttributeSyntax.arguments.as(LabeledExprListSyntax.self)` | Handles all edge cases, preserves trivia |
| Extracting parameter labels | String manipulation | `LabeledExprSyntax.label?.text` | Type-safe, handles optional labels |
| Generating PropertyConfig | String interpolation | `FunctionCallExprSyntax` + `LabeledExprListSyntax` | Preserves formatting, proper AST |
| Database persistence | Custom file format | FailingExampleDatabase (JSON) | Git-friendly, versioned, already implemented |
| TestIdentifier | Manual hashing | TestIdentifier.init from ISP-0004 | Handles module, file, function, signature |

**Key insight:** SwiftSyntax is verbose but deterministic. String interpolation is brittle and breaks formatting.

## Common Pitfalls

### Pitfall 1: RegressionBank vs FailingExampleDatabase Confusion

**What goes wrong:** PropertyConfig uses `RegressionBank`, ISP-0004 uses `FailingExampleDatabase`, they're incompatible types

**Why it happens:** ISP-0004 was implemented after PropertyRunner's regression infrastructure

**How to avoid:**
- Check if `RegressionBank` is a protocol or concrete type
- If protocol: make `FailingExampleDatabase` conform
- If concrete type: replace with `FailingExampleDatabase` or create adapter

**Warning signs:**
- Type mismatch errors when passing database to PropertyConfig
- Tests compile but crash at runtime with "Type not found"

### Pitfall 2: Macro Cannot Access Library Types

**What goes wrong:** `import InvariantSwift` in macro target fails

**Why it happens:** Macro targets are build plugins, separate compilation unit

**How to avoid:**
- Generate code that *references* library types (strings become identifiers)
- Use `DeclReferenceExprSyntax(baseName: .identifier("FailingExampleDatabase"))`
- Never try to instantiate library types in macro code

**Warning signs:**
- "Cannot find type 'FailingExampleDatabase' in scope" in macro target
- Macro tests pass but expanded code doesn't compile

### Pitfall 3: @Regression + @Reproduce Conflict

**What goes wrong:** User applies both macros, behavior is undefined

**Why it happens:** No validation that macros are mutually exclusive

**How to avoid:**
- In PropertyMacro expansion, check for both configs
- Emit diagnostic if both present
- Document that they're mutually exclusive

**Warning signs:**
- Test replays @Reproduce seed but also checks database
- Confusing behavior where one macro "wins"

### Pitfall 4: Database Disabled But Macro Present

**What goes wrong:** @Regression macro present but `INVARIANT_EXAMPLES_DISABLED=1`

**Why it happens:** Environment variable disables database but macro still configures it

**How to avoid:**
- Check `FailingExampleConfig.isEnabled` at runtime
- Generate code that respects environment config
- Or: make macro expansion respect build-time flags

**Warning signs:**
- Macro present but no examples saved
- Silent failure when database is disabled

### Pitfall 5: PropertyId Stability

**What goes wrong:** PropertyId changes across runs, examples not replayed

**Why it happens:** PropertyId includes unstable components (line numbers, temp paths)

**How to avoid:**
- Use stable identifiers: module + file + function name
- Exclude line numbers, absolute paths
- Use TestIdentifier pattern from ISP-0004 (already stable)

**Warning signs:**
- Examples saved but never replayed
- Database grows unbounded with duplicates

### Example 2: Config Extraction (adapted from ReproduceExtractor)

```swift
// Source: Sources/InvariantSwiftMacros/ReproduceMacro.swift (lines 58-117)
public enum RegressionExtractor {
  public static func extractConfig(from funcDecl: FunctionDeclSyntax) -> RegressionConfig? {
    for attr in funcDecl.attributes {
      guard let attrSyntax = attr.as(AttributeSyntax.self),
        let ident = attrSyntax.attributeName.as(IdentifierTypeSyntax.self),
        ident.name.text == "Regression"
      else { continue }

      return parseRegressionAttribute(attrSyntax)
    }
    return nil
  }

  private static func parseRegressionAttribute(_ attr: AttributeSyntax) -> RegressionConfig? {
    guard let args = attr.arguments?.as(LabeledExprListSyntax.self) else {
      return RegressionConfig.default  // No args = default config
    }

    var database: DatabaseReference? = .shared
    var replayFirst: Bool = true
    var maxExamples: Int?

    for arg in args {
      let label = arg.label?.text

      switch label {
      case "database":
        database = extractDatabaseReference(from: arg.expression)

      case "replayFirst":
        if let boolLiteral = arg.expression.as(BooleanLiteralExprSyntax.self) {
          replayFirst = boolLiteral.literal.tokenKind == .keyword(.true)
        }

      case "maxExamples":
        maxExamples = extractInt(from: arg.expression)

      default:
        break
      }
    }

    return RegressionConfig(
      database: database,
      replayFirst: replayFirst,
      maxExamples: maxExamples
    )
  }
}
```

## Open Questions

Things that couldn't be fully resolved:

1. **RegressionBank vs FailingExampleDatabase**
   - What we know: PropertyConfig uses `RegressionBank?`, ISP-0004 added `FailingExampleDatabase`
   - What's unclear: Is RegressionBank a protocol? Can we replace it?
   - Recommendation: Check RegressionBank definition. If protocol, make FailingExampleDatabase conform. If type, replace with FailingExampleDatabase.

2. **PropertyId format**
   - What we know: PropertyRunner expects `propertyId: String?`
   - What's unclear: What format? Does it match TestIdentifier.storageKey?
   - Recommendation: Use `TestIdentifier.storageKey` format (module::file::function::signature)

3. **Database parameter syntax**
   - What we know: Need to reference FailingExampleDatabase.shared in macro
   - What's unclear: Support custom databases? How to express in macro syntax?
   - Recommendation: Start with `.shared` only, add custom database support later

4. **@Regression + @Reproduce interaction**
   - What we know: Both configure PropertyConfig
   - What's unclear: Are they mutually exclusive? Do they compose?
   - Recommendation: Make mutually exclusive with diagnostic error

5. **Automatic markFixed() behavior**
   - What we know: PropertyRunner.runPropertyWithRegressions marks examples fixed on success (line 862)
   - What's unclear: Is this the desired behavior for @Regression?
   - Recommendation: Yes, keep this behavior. Fixed examples are removed automatically.
