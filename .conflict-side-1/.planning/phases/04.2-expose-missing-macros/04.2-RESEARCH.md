# Phase 04.2: Expose Missing Macros - Research

**Researched:** 2026-01-23
**Domain:** Swift macro system, SwiftSyntax, property-based testing
**Confidence:** HIGH

## Summary

Research confirms that @LawChecked and @DeriveGen macros have complete implementations (1,118 and 685 lines respectively) but lack public API declarations in `Sources/InvariantSwift/Macros/`. The codebase follows a clear separation pattern where macro *implementations* live in `InvariantSwiftMacros/` (as compiler plugins) and macro *declarations* live in `InvariantSwift/Macros/` (as public API). Both macros are partially integrated: DeriveGenMacro is registered in MacroPlugin.swift, but neither has declaration files following the established pattern from ArbitraryMacroDeclaration.swift and BusinessRuleMacroDeclaration.swift.

**Primary recommendation:** Create declaration files using @attached(member) and @attached(extension) attributes following the exact pattern from existing macros, update docs/MACROS.md to reflect actual availability, and create comprehensive SwiftSyntaxMacrosTestSupport-based tests for 99% coverage.

### Pattern 1: Macro Declaration File Structure

**What:** Public API declaration file in `Sources/InvariantSwift/Macros/` with @attached attributes
**When to use:** For every macro implementation in InvariantSwiftMacros
**Example:**

```swift
// Source: ArbitraryMacroDeclaration.swift (verified pattern)
import InvariantSwift
import InvariantSwiftExperimental
import InvariantSwiftCore
import Foundation

@attached(member, names: named(arbitrary), named(shrink))
@attached(extension, conformances: Generatable)
public macro Arbitrary(
  shrink: ArbitraryShrinkStrategy = .automatic,
  constraints: [String: String] = [:]
) = #externalMacro(module: "InvariantSwiftMacros", type: "ArbitraryMacro")

/// Shrinking strategy for @Arbitrary macro.
public enum ArbitraryShrinkStrategy: Sendable {
  case automatic
  case none
  case toEmpty
  case dropFields
}
```

**Key components:**
1. Import required modules (InvariantSwift, InvariantSwiftCore, InvariantSwiftExperimental, Foundation)
2. @attached attribute(s) declaring macro role and generated member names
3. Public macro declaration with #externalMacro pointing to implementation
4. Supporting enums/types used in macro parameters

### Pattern 3: Macro Implementation Structure

**What:** Macro implementation in InvariantSwiftMacros with MemberMacro and/or ExtensionMacro conformance
**When to use:** Creating new macro functionality
**Example:**

```swift
// Source: DeriveGenMacro.swift (verified existing implementation)
import SwiftCompilerPlugin
import SwiftSyntax
import SwiftSyntaxBuilder
import SwiftSyntaxMacros
import Foundation

public struct DeriveGenMacro: MemberMacro, ExtensionMacro {

  public static func expansion(
    of node: AttributeSyntax,
    providingMembersOf declaration: some DeclGroupSyntax,
    conformingTo protocols: [TypeSyntax],
    in context: some MacroExpansionContext
  ) throws -> [DeclSyntax] {
    // Extract configuration from macro arguments
    let config = try extractConfiguration(from: node, context: context)

    // Analyze the type structure
    guard let analyzed = try analyzeTypeStructure(declaration, context: context) else {
      throw DeriveGenError.unsupportedType("Cannot derive generator for this type")
    }

    // Generate the generator implementation
    let generatorMember = try generateGeneratorMember(
      for: analyzed,
      config: config,
      context: context
    )

    return [generatorMember]
  }

  public static func expansion(
    of node: AttributeSyntax,
    attachedTo declaration: some DeclGroupSyntax,
    providingExtensionsOf type: some TypeSyntaxProtocol,
    conformingTo protocols: [TypeSyntax],
    in context: some MacroExpansionContext
  ) throws -> [ExtensionDeclSyntax] {
    // Create extension with Generatable conformance
    let extensionDecl = try ExtensionDeclSyntax(
      "extension \(type.trimmed): Generatable"
    ) {
      // Empty - the actual implementation is in the member macro
    }
    return [extensionDecl]
  }
}
```

### Pattern 4: Macro Testing with assertMacroExpansion

**What:** Test macro expansion using SwiftSyntaxMacrosTestSupport
**When to use:** Testing every macro (required for 99% coverage)
**Example:**

```swift
// Source: ArbitraryMacroTests.swift (verified existing pattern)
import XCTest
import SwiftSyntaxMacros
import SwiftSyntaxMacrosTestSupport
import InvariantSwiftCore
@testable import InvariantSwiftMacros

final class ArbitraryMacroTests: XCTestCase {

  let testMacros: [String: Macro.Type] = [
    "Arbitrary": ArbitraryMacro.self
  ]

  func testSimpleStructExpansion() {
    assertMacroExpansion(
      """
      @Arbitrary
      struct User {
          let name: String
          let age: Int
      }
      """,
      expandedSource: """
        struct User {
            let name: String
            let age: Int

            public static var arbitrary: Gen<User> {
                Gen.zip(Gen<String>.string, Gen<Int>.int).map {
                    User(name: $0, age: $1)
                }
            }

            public static var shrink: Shrink<User> {
                Shrink { value in
                    var results: [User] = []
                    for shrunkName in Gen<String>.string.shrink.shrink(value.name) {
                        results.append(User(name: shrunkName, age: value.age))
                    }
                    for shrunkAge in Gen<Int>.int.shrink.shrink(value.age) {
                        results.append(User(name: value.name, age: shrunkAge))
                    }
                    return results
                }
            }
        }

        extension User: Generatable {
        }
        """,
      macros: testMacros
    )
  }
}
```

**CRITICAL:** Whitespace-sensitive matching. Expected expansion must exactly match generated code including indentation.

### Anti-Patterns to Avoid

- **String interpolation for code generation:** NEVER use `DeclSyntax(stringLiteral: "...")`. ALWAYS use SwiftSyntax AST builders (see Sources/InvariantSwiftMacros/CLAUDE.md).
- **Throwing from expansion:** Return empty array with diagnostic instead of throwing errors.
- **Force unwrapping:** Use guard statements, not force unwrap (!) in macro implementations.
- **Missing plugin registration:** All macro implementations MUST be registered in MacroPlugin.swift.
- **Incomplete @attached declarations:** Must declare all generated member names in `names:` parameter.

## Don't Hand-Roll

Problems that look simple but have existing solutions:

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|

## Common Pitfalls

### Pitfall 1: Missing Macro Plugin Registration

**What goes wrong:** Macro implementation exists, declaration exists, but compiler error "External macro implementation type 'MacroName' could not be found"
**Why it happens:** Macro not registered in MacroPlugin.swift `providingMacros` array
**How to avoid:** After creating macro implementation, immediately add to MacroPlugin.swift before creating declaration
**Warning signs:** Build succeeds but macro usage fails with "could not be found" error

### Pitfall 2: @attached(member, names:) Declaration Mismatch

**What goes wrong:** Compiler error "Cannot find 'memberName' in scope" when using generated member
**Why it happens:** Generated member name not declared in @attached attribute's `names:` parameter
**How to avoid:** Declare ALL generated member names upfront in @attached attribute (e.g., `names: named(arbitrary), named(shrink)`)
**Warning signs:** Macro expands successfully in tests but fails when used in actual code

**Example:**
```swift
// WRONG - missing named(shrink)
@attached(member, names: named(arbitrary))
public macro Arbitrary(...) = ...

// CORRECT - all members declared
@attached(member, names: named(arbitrary), named(shrink))
public macro Arbitrary(...) = ...
```

### Pitfall 3: SwiftSyntax Version Incompatibility

**What goes wrong:** Build errors about missing symbols or changed APIs in SwiftSyntax
**Why it happens:** SwiftSyntax has breaking changes between versions, even minor/patch versions
**How to avoid:** Use exact version pinning (`.package(url: "...", exact: "602.0.0")`) in Package.swift
**Warning signs:** Macro code that worked locally fails in CI with different Swift version

### Pitfall 4: Whitespace Sensitivity in Macro Expansion Tests

**What goes wrong:** Test fails with diff showing only whitespace differences
**Why it happens:** assertMacroExpansion does exact string comparison including all whitespace
**How to avoid:** Copy-paste expected expansion from test failure output, preserve exact indentation
**Warning signs:** Test output shows identical code but different indentation levels

**Example:**
```swift
// WRONG - spaces vs tabs, wrong indentation depth
expandedSource: """
  struct User {
  let name: String
  }
"""

// CORRECT - exact indentation matching generated code
expandedSource: """
struct User {
    let name: String
}
"""
```

### Pitfall 5: Macro Target Dependency Restrictions

**What goes wrong:** Build error "Cannot find type 'Gen' in scope" when implementing macro
**Why it happens:** Macro targets (CompilerPlugin) cannot import runtime library targets (InvariantSwift)
**How to avoid:** Macro implementations must be pure SwiftSyntax AST generation. No runtime dependencies.
**Warning signs:** Trying to import InvariantSwift in macro implementation file

**Reference:** Package.swift lines 100-115 show InvariantSwiftMacros target has ZERO dependencies on InvariantSwift

### Pitfall 6: Documentation Drift (Current Issue)

**What goes wrong:** docs/MACROS.md documents @LawChecked and @DeriveGen but they're not publicly accessible
**Why it happens:** Documentation written before public declarations created, or declarations removed without doc updates
**How to avoid:** Update docs/MACROS.md in same commit as declaration changes
**Warning signs:** Documentation describes features that produce compiler errors when used

**Current state:**
- docs/MACROS.md lines 270-390 document @LawChecked and @DeriveGen with full usage examples
- Reality: No LawCheckedMacroDeclaration.swift or DeriveGenMacroDeclaration.swift files exist
- Users attempting to use these macros get "Cannot find 'LawChecked' in scope" errors
