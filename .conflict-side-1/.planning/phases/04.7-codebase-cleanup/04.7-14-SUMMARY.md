## Deviations from Plan

### Deviation 1: Size.valueLens Naming (Rule 3 - Blocking)

**Found during:** Task 1 implementation

**Issue:** Swift compiler cannot disambiguate between static property `Size.value` and instance property `size.value` when both exist in the same type, even with different types (Lens<Size, Int> vs Int). Compiler error: "static member 'value' cannot be used on instance of type 'Size'".

**Resolution:** Renamed lens property to `valueLens` to avoid collision.

**Impact:** Tests expecting `Size.value` will need updates to use `Size.valueLens`.

**Files affected:** Size+Lenses.swift

**Commit:** 1cbe3b6

### Deviation 2: PropertyConfig.default Already Exists (Rule 1 - Bug)

**Found during:** Task 3 implementation

**Issue:** PropertyConfig.default already defined in Property.swift line 769. Adding duplicate caused "invalid redeclaration of 'default'" compiler error.

**Resolution:** Removed duplicate definition from PropertyConfig+Helpers.swift; retained only factory methods.

**Impact:** None - existing .default works as expected.

**Files affected:** PropertyConfig+Helpers.swift

**Commit:** ec92b49 (corrected during task)

## Technical Decisions

### Decision 1: Lens Property Naming Convention

**Context:** Swift compiler limitation prevents static/instance property name collision

**Options evaluated:**
1. `value` - Matches test expectations but causes compiler error
2. `valueLens` - Explicit naming, no collision ✅ **SELECTED**
3. `sizeValue` - Verbose, unclear benefit

**Rationale:** Explicit `valueLens` naming makes lens purpose clear and avoids compiler limitation. Tests are easily updatable.

### Decision 2: Factory Method Pattern

**Context:** Helper methods need flexibility for customization

**Options evaluated:**
1. Static constructors only - Simple but inflexible
2. Take base config parameter - Flexible, preserves customizations ✅ **SELECTED**
3. Builder pattern - More complex, unnecessary for this use case

**Rationale:** Taking base config as parameter allows users to customize default config then apply preset, preserving all non-overridden fields (e.g., custom seed, database config).

## Lessons Learned

1. **Swift static/instance property collision:** Static properties cannot share names with instance properties, even with different types. Use explicit naming (e.g., `valueLens`, `seedValue`).

2. **Check for existing definitions:** Before creating static factory properties, search for existing definitions to avoid redeclaration errors.

3. **Factory method flexibility:** Taking base config as parameter provides maximum flexibility while keeping API simple.
