## Decisions Made

**1. Use Lens suffix naming pattern**
- **Rationale:** Swift compiler cannot distinguish between static lens property and instance property with same name. Following Size.valueLens pattern, use suffix to avoid collision.
- **Alternative considered:** KeyPath-only approach failed (still caused ambiguity)
- **Impact:** Test file requires updates to use `iterationsLens` instead of `iterations`

**2. Fix PropertyRunner+Coverage.swift and FlakeHunter.swift name collisions**
- **Rationale:** Adding static `iterations` and `seed` properties caused compiler errors in files accessing `config.iterations` and `config.seed` (Swift couldn't distinguish)
- **Fix:** Extract to local variables before use: `let executionCount = config.iterations`
- **Impact:** Rule 1 deviation (bug) - required for compilation

## Issues Encountered

**Swift static/instance property name collision:**
- **Problem:** Swift compiler cannot distinguish `PropertyConfig.iterations` (static lens) from `config.iterations` (instance property access) in the same scope
- **Resolution:** Use Lens suffix naming pattern (iterationsLens) following Size.valueLens precedent
- **Lesson:** When adding static properties to types with instance properties, avoid name collisions by using suffixes
